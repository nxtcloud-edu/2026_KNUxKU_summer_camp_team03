# Quill · 리포트를 읽어주는 금융 과외

> **2026_KNUxKU_summer_camp_team03** · `DESIGN` 브랜치
> 강원대x고려대 Summer Agentic AI 심화 몰입 캠프 3팀 레포지토리입니다.
> 이 브랜치에는 **디자인/프런트엔드 프로토타입**이 들어 있습니다.

증권사 리포트를 근거로, 사회초년생과 바쁜 직장인에게 **채권·ETF 중심 자산 배분**을
눈높이에 맞춰 설명하는 서비스의 **화면 프로토타입**입니다.

> ⚠️ **화면 검증용입니다.** DB·수집 파이프라인·실제 LLM은 아직 붙지 않았습니다.
> 화면에 나오는 증권사 리포트·발췌문·수익률·시황은 **전부 지어낸 샘플**이며 실제 자료가
> 아닙니다. 투자 권유나 자문이 아닙니다.

## 1. 실행하기

### 준비물 — Node.js 하나면 됩니다

| 필요한 것 | 확인 방법 | 없다면 |
|---|---|---|
| Node.js 18 이상 | 터미널에 `node -v` | [nodejs.org](https://nodejs.org)에서 LTS 설치 |
| Git | `git --version` | [git-scm.com](https://git-scm.com) |

DB도, API 키도, 회원가입도 필요 없습니다. 받아서 바로 실행하면 됩니다.

### 처음 한 번

```bash
git clone -b DESIGN https://github.com/nxtcloud-edu/2026_KNUxKU_summer_camp_team03.git
cd 2026_KNUxKU_summer_camp_team03/frontend
npm install
```

`npm install`은 1~2분 걸립니다. 폰트까지 같이 받기 때문입니다.

### 실행

```bash
npm run dev
```

터미널에 아래처럼 뜨면 성공입니다. 주소를 브라우저에 붙여 넣으세요.

```
  ➜  Local:   http://localhost:5174/
```

**끄는 법**: 터미널에서 `Ctrl + C`

### 윈도우에서 더 간단하게

프로젝트 폴더(`frontend`가 아니라 그 위)에서 PowerShell로:

```powershell
powershell -ExecutionPolicy Bypass -File .\start.ps1   # 실행 + 브라우저 자동 열기
powershell -ExecutionPolicy Bypass -File .\stop.ps1    # 종료
```

> `start.ps1`과 `stop.ps1`은 **UTF-8 BOM**으로 저장돼 있어야 합니다. BOM이 없으면
> Windows PowerShell 5.1이 CP949로 읽어서 한글 부분에서 에러가 납니다. 편집할 일이
> 있으면 인코딩을 확인하세요.

### 잘 안 될 때

| 증상 | 원인과 해결 |
|---|---|
| `npm: command not found` | Node.js가 없습니다. 설치 후 터미널을 새로 여세요 |
| 포트 5174가 이미 사용 중 | 다른 창에서 이미 켜져 있습니다. `stop.ps1` 실행 또는 그 창에서 `Ctrl+C` |
| 화면이 하얗게만 나옴 | `frontend` 폴더에서 실행했는지 확인. `npm install`을 건너뛰지 않았는지도 |
| 한글이 깨져 보임 | 폰트를 아직 받는 중입니다. 몇 초 뒤 새로고침 |

## 2. 어디를 보면 되나요

실행하면 대화 화면이 먼저 뜹니다. 아래 순서로 둘러보시면 흐름이 한 번에 잡힙니다.

| 주소 | 화면 | 여기서 볼 것 |
|---|---|---|
| `/` | **대화** (메인) | 추천 질문을 누르면 답변이 **만년필로 쓰이듯** 흐릅니다 |
| `/onboarding` | 성향 6문항 | 답을 고칠 때마다 오른쪽 점수·비중이 **즉시** 다시 계산됩니다 |
| `/portfolio` | 내 포트폴리오 | 슬라이더를 놓으면 **1.2초 뒤** 에이전트 조정안이 도착합니다 |
| `/library` | 리포트 서재 | 수집·태깅된 리포트 목록 |
| `/admin` | 관리자 콘솔 | 수집 현황·검수 큐·배분표 편집 |

### 꼭 눌러 보셔야 하는 것 세 가지

**1. `/` 에서 "금리가 내리면 뭘 사야 하나요?"**
한 질문에 이 서비스의 약속이 전부 나옵니다.
- 위에 **가드레일 안내**가 붙습니다 — "무엇을 사고팔지는 정해 드릴 수 없어요"
- 답변이 **출처를 밝히며** 시작합니다 — "○○증권 「…」에 따르면"
- 리포트끼리 의견이 갈리면 **합치지 않고 나란히** 보여 줍니다
- 아래에 **각주 번호**가 붙고, 오른쪽 패널의 같은 번호와 이어집니다

**2. 입력창 아래 "에이전트 트레이스"**
어떤 에이전트가 몇 ms 걸렸는지 그대로 펼쳐집니다.
Guardrails → Supervisor → Triage → Analysis → Recommendation

**3. `/portfolio` 에서 슬라이더를 좌우로**
숫자가 즉시 따라오고, 손을 떼면 한 박자 늦게 에이전트 의견이 옵니다.
**"근거 없는 제안 1건 폐기"**가 화면에 그대로 남는 것도 확인해 보세요.

## 3. 이 프로토타입이 지키는 약속

문서가 아니라 **코드로** 강제합니다.

| 약속 | 강제하는 곳 |
|---|---|
| 배분 숫자는 코드가 계산한다. LLM은 못 쓴다 | `src/lib/quant.ts` |
| 근거 없는 조정은 폐기한다 | `applyAdjustments()` |
| 조정은 ±10%p를 넘을 수 없다 | 하드 클램프 |
| 현금성은 5% 아래로 안 내려간다 | 조정 후에도 재확인 |
| 매수·매도·예측은 답하지 않는다 | `src/lib/guardrails.ts` |
| 근거가 없으면 답을 만들지 않는다 | 고정 폴백 문구 |
| 의견이 갈리면 합치지 않는다 | `ParallelViews` |

### 추천 알고리즘 3단계

```
1단계  Capacity(객관: 기간·저축여력·나이) / Tolerance(주관: MDD·손실반응·목표)
       따로 산출 → risk_score = capacity × 0.4 + tolerance × 0.6
                                                    ↓
2단계  현금성 5% 먼저 떼기 → 남은 95%를 risk_score에 비례 배분 (선형 보간)
                                                    ↓
3단계  에이전트가 델타(±%p)만 제안 → 파이썬(여기서는 TS)이 검증
       · 근거 리포트 ID 없으면 폐기
       · ±10%p 하드 클램프
       · 합계 100 재정규화
```

1~2단계는 순수 연산이라 **밀리초 단위**로 끝납니다. 그래서 슬라이더가 즉시 반응합니다.
3단계만 한 박자 늦게 옵니다. 그 시차가 두 레이어의 차이를 그대로 보여 줍니다.

## 4. 디자인

### 색 — 차가운 아이보리 위의 먹색, 강조는 골드

| 용도 | 값 | 메모 |
|---|---|---|
| 바탕 | `#F7F6F3` | 미색에서 노란기를 뺀 중성. 종이가 아니라 도구로 보이게 |
| 글자 | `#16181C` | 먹색. 회색으로 흐리지 않음 |
| 골드 | `#A8843C` | 바탕 대비 **4.6:1 (WCAG AA 통과)** |
| 경고 | `#B3541E` | 일부러 골드 계열을 피함 |

> 경고색을 골드 계열로 두면 강조색에 묻혀 안 보입니다. 금융 화면에서 "원금 손실 가능"이
> 안 보이는 건 위험해서, 톤 통일을 깨고 색상을 벌렸습니다.

골드는 **선·수치·활성 표시·1차 버튼**까지만 씁니다. 면으로 칠하지 않습니다.
고급스러움은 금색 면적이 아니라 여백·정렬·선 굵기에서 나온다는 전제입니다.

### 글자 — 3단 구성

| 단계 | 서체 | 쓰는 곳 |
|---|---|---|
| 만년필 명조 | **고운바탕** | 챗봇 답변 본문, 큰 제목, 큰 수치 |
| 영문 필기체 | **Italianno** | 워드마크 (대문·로그인 딱 2곳) |
| 본문 | **Pretendard** | 내 질문, UI, 숫자 전부 |

**나눔손글씨 펜은 뺐습니다.** 만년필이 아니라 볼펜·사인펜 손글씨라 키울수록 우아해지는
게 아니라 어설퍼집니다. 고운바탕은 세로획이 굵고 가로획이 얇아 **펜촉의 필압이 글자에
남습니다** — 우아함이 거기서 나옵니다.

답변 본문의 만년필체는 입력창 아래 **"답변 만년필체 켬/끔"** 토글로 끌 수 있습니다.

### 버튼 — 경계감 없이

테두리를 쓰지 않습니다. 색면·여백·아주 옅은 그림자로만 누를 곳임을 알립니다.
누를 때는 그림자를 넣는 대신 살짝 가라앉기만 합니다.
다만 **키보드 포커스 표시는 남겼습니다** — 경계선을 지운 디자인에서 같이 지워지기 쉬운데,
그러면 키보드로 쓰는 사람이 지금 어디에 있는지 알 수 없습니다.

### 답변이 쓰이는 방식

글자가 **왼쪽에서 오른쪽으로 훑이며** 나타나고, 잉크 색이 같이 앉습니다
(골드 = 젖음 → 먹색 = 마름, 460ms). 그 끝을 **만년필 촉**이 따라갑니다.

속도는 일부러 고르지 않게 뒀습니다. 균일하면 아무리 꾸며도 "출력"으로 읽힙니다.

| 글자 | 걸리는 시간 |
|---|---|
| 한글 한 음절 | 34-60ms (획이 많음) |
| 영문·숫자 | 19-33ms |
| 띄어쓰기 | 52-78ms (펜을 뗌) |
| 마침표 | 300ms 이상 (손이 멈춤) |

> **진짜 획순대로 그리는 건 불가능합니다.** 한글은 완성형만 1만 1천 자가 넘고 글자마다
> 획 경로 데이터가 필요합니다. 지금은 획을 그리는 게 아니라 펜이 지나가는 방향을
> 흉내 내는 것입니다.

모션 최소화를 켠 사용자에게는 번짐도 흔들림도 나가지 않습니다.

### 근거 표현 — 각주처럼

알약 칩을 걷어내고 **각주 번호**로 바꿨습니다. 칩은 개수가 늘수록 색 덩어리가 되어
정작 읽어야 할 답변보다 시끄러워집니다. 근거가 3건만 돼도 그랬습니다.

상자·테두리·그림자를 쓰지 않고, 양끝이 사라지는 **골드 헤어라인**으로만 구분합니다.
답변 아래 번호와 오른쪽 패널의 번호가 같아서 눈으로 이어 따라갈 수 있습니다.

## 6. 로그인 (선택)

**키가 없으면 로그인 없이 그냥 돌아갑니다.** 지금 상태가 그렇습니다.
켜려면 아래 순서를 **반드시 지켜야** 합니다.

```
1) Supabase 프로젝트 생성
2) SQL Editor에서  supabase/schema.sql  실행
3) 이어서          supabase/rls.sql     실행   ← 절대 건너뛰지 말 것
4) frontend/.env.local 파일을 만들고 아래 두 줄 입력
5) npm run dev 다시 시작
```

```bash
VITE_SUPABASE_URL=https://your-project.supabase.co
VITE_SUPABASE_ANON_KEY=your-anon-public-key
```

> ### ⚠️ 3번을 건너뛰면 안 되는 이유
>
> anon 키는 브라우저에 그대로 노출됩니다. 그게 정상이고 숨길 방법도 없습니다.
> **보안은 키가 아니라 RLS 정책이 만듭니다.**
>
> RLS를 걸지 않은 채 키만 넣으면, 그 키를 주운 사람이 **모든 사용자의 시드머니와 대화
> 기록을 읽을 수 있습니다.** 로그인 있는 무방비가 로그인 없는 무방비보다 위험합니다 —
> 안전하다고 믿게 만들기 때문입니다.
>
> **`service_role` 키는 절대 넣지 마세요.** 그 키는 RLS를 통째로 우회합니다.

`.env.local`은 `.gitignore`에 있어 커밋되지 않습니다.

키를 넣으면 `/admin`이 로그인 없이는 열리지 않습니다. **지금은 무방비라 상단에 경고
띠가 떠 있습니다.** 외부에 올리기 전에 반드시 붙여야 합니다.

## 7. 아직 안 된 것 (정직하게)

- **실데이터 연동** — 리포트는 전부 `lib/mock.ts`의 샘플입니다
- **실제 LLM** — 챗봇은 규칙 매칭입니다. RAG는 다음 단계
- **DB 연결** — 온보딩 답과 대화는 브라우저에만 저장됩니다
- **관리자 인증** — 화면 차단만 있고 서버 권한 통제는 RLS를 붙여야 생깁니다
- **법률 검토** — "권유"가 아닌 "해설"로 쓰고 있지만 법률 의견은 아닙니다
- **폰트 용량** — 한글 웹폰트 3.5MB. 배포 전 서브셋 필요

### 팀에서 정해야 할 것

- 3페이지의 정체 — 지금은 4초 뒤 자동으로 넘어가는 통과 화면입니다
- Supabase 프로젝트를 누가 만들지
- 답변 만년필체를 켤지 끌지 (토글로 둘 다 되니 보고 정하면 됩니다)
